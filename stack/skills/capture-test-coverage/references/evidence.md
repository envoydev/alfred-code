# Evidence appendix - the runs these coverage rules were written from

An audit appendix, not a run-time load: read it when a rule in SKILL.md or `doc-shape.md` looks like
ceremony, never while capturing.

- **Coverage stays outside the build flows (SKILL.md, the opening).** A seat babysitting an
  instrumented run burned about half its cost idling on the wait.
- **The mode question joins the first capture's other asks (Analysis on the FIRST capture).** A first
  capture asked Docker-handling and the bar in one call and never asked the mode.
- **Long-running categories stay out unless asked (3. MEASURE).** An unasked replay run consumed 41GB
  of disk before being killed, and the user had to add a hand-written rule to stop it recurring.
- **The narrative is capped while reconciling (`doc-shape.md`).** One COVERAGE.md reached 951 lines,
  31% never-pruned narrative, ~15-16k tokens per round-start read of which ~24% was operationally
  needed.
- **One write per doc, never a per-claim edit stream (`doc-shape.md`).** 24 serial edits to one
  COVERAGE.md in a single session - the worst doc churn of a 15-session audit.

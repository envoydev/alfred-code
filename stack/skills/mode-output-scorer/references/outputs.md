# The scorer's outputs

Each output the scorer grades: who produces it, what is graded, its rubric, its runs per attempt, whether it is graded without a typed stack, and the docs its grader is handed (paths under the docs root; a folder ends with `/`, `target` is the plan file the draft names, `skill:` sits beside this skill's folder). `scripts/scorecard.js` holds the same map as `OUTPUTS`, and a test fails when the two differ. The stack's inventory, `docs/alfred-code.html`, links here.

The map's two homes and the run book's two names are both listed: the grader is handed whichever exists - the map under `awareness/` since 2026-10-29, at its legacy `architecture/` home in an install not yet updated - and of the run book only the one the docs engine reads, so a hand copy left at its legacy name is not handed.

An automatic output is graded while `scorer: on` names it (`ALFRED_CODE_SCORER_OUTPUTS`, all three when unset) - on for the session after `--mode-output-scorer-on` right after a task-, capture-, loop-, issue- or mode- command, else while `ALFRED_CODE_SCORER=1`; every output, the automatic ones included, is graded when the user stacks `/mode-output-scorer` onto the request. A seat never runs the scorer: the session that receives its report grades what it writes or acts on.

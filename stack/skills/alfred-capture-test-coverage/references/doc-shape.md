# COVERAGE.md - the shape, and how a re-run reconciles it

Read at step 5 WRITE, before the write.

`<docs-path>/test-coverage/COVERAGE.md`, clean scannable Markdown per the `markdown-style` skill, tables over prose: a first-line stamp `Captured: <branch>@<short-sha>, <YYYY-MM-DD>`, `+dirty` appended when the tree held uncommitted changes (the numbers describe exactly that code - any other branch, and any reader of a dirty stamp, re-measures, never trusts), the requirement + override + applied exclusions, a per-stack verdict table (surface, line %, requirement, verdict), a per-module table per surface (module, line %, the uncovered hot spots), and the weak points in their three buckets - Must fix tiered with a simplify-testing action each, Worth knowing with promotion conditions, Deliberate tradeoffs with reasons. Suite-quality smells from the digests land in those same buckets, each keeping its `red-check pending` label - the analysis seat is read-only and cannot prove a smell, so the label routes the proof to whoever rewrites the spec (the coverage loop's fix step runs it). A smell the loop DISPROVED by red-check carries `red-check: disproved <date>` on its entry instead - honor it like a recorded decision and never re-flag that spec for the same smell. Re-run: reconcile in place - resolved weak points drop off, new gaps land, stale numbers are replaced. Cap the narrative while reconciling: keep the current capture's headline, fold older per-round/per-capture prose into a one-line-per-round changelog at the doc's END - the doc otherwise only grows, and every loop round pays its read (measured: one COVERAGE.md reached 951 lines, 31% never-pruned narrative, ~15-16k tokens per round-start read of which ~24% was operationally needed). Put a `## Resume` section right under the stamp - requirement, exclusions, open weak points by tier: exactly what a resumed round needs - so round starts read that section ranged instead of the whole file; it is DERIVED from the full sections below (regenerated whole each reconcile, the full sections authoritative on any mismatch), so the duplication cannot drift. Compose the reconcile in-session and land it in one write (or one batched edit pass) per doc - never a per-claim edit stream (measured: 24 serial edits to one COVERAGE.md in a single session, the worst doc churn of a 15-session audit). Create the folders only when absent; write ONLY under `<docs-path>/test-coverage/` - never source, never a test, never another doc.

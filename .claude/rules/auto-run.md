# Load auto-run when the user is away

- When the user says they are away or gone, or to run 'without stopping', 'without asking me', in 'auto mode', to turn auto-run on ('enable auto run'), or to take the recommended options, load the `auto-run` skill before the first step - even when the work looks like it will need no ask. Why: its description alone did not fire on 'I am away - run the lint fixes one by one without stopping' (two probes, 2026-10-27), and the user should not have to name it.
- The `kit status` line the status hook adds to every request says whether the mode is on: with `auto_run=on`, from the settings or from this session, load `auto-run` before the first ask or review handoff. `auto_run=off (this session)` means the user stopped it.
- What the user tells a session about auto-run outranks the settings, both ways (the user, 2026-11-15): asked to turn it on or off, enable or disable it, start or stop it - in any words - do as said for the rest of the session. The status hook records a request that opens with such words; when that request's `kit status` line does not show the switch as `(this session)`, append `Auto-run: on - <date>` or `Auto-run: off - <date>` to `kit-session.md` in the session scratchpad yourself.
- Where no `kit status` line arrives: run `node .claude/kit/settings.mjs` before the session's first ask, and after a compaction Read `kit-session.md` in the session scratchpad - its last `Auto-run:` line is how the mode outlives the summary.

# Load auto-run when the user is away

- When the user says they are away or gone, or to run 'without stopping', 'without asking me', in 'auto mode', or to take the recommended options, load the `auto-run` skill BEFORE the first step - even when the work looks like it will need no ask. Why: its description alone did not fire on 'I am away - run the lint fixes one by one without stopping' (two probes, 2026-10-27), and the user should not have to name it.
- The `kit status` line the status hook adds to every request says whether the mode is on. `auto_run=on` is either the user's standing default for this project (`KIT_AUTO_RUN` in their own settings) or what they said in this session: either way load `auto-run` before the first ask or review handoff, and say so when it came from the settings. `auto_run=off (this session)` means the user stopped it.
- Where no `kit status` line arrives: run `node .claude/kit/settings.mjs` before the session's first ask, and after a compaction Read `kit-session.md` in the session scratchpad - its last `Auto-run:` line is how the mode outlives the summary.

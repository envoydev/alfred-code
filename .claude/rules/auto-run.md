# Load auto-run when the user is away

- When the user says they are away or gone, or to run 'without stopping', 'without asking me', in 'auto mode', to turn auto-run on ('enable auto run'), or to take the recommended options, load the `auto-run` skill before the first step - even when the work looks like it will need no ask. Why: its description alone did not fire on 'I am away - run the lint fixes one by one without stopping' (two probes, 2026-10-27), and the user should not have to name it.
- The `kit status` line the status hook adds to every request says whether the mode is on: with `auto_run=on`, whatever its source, load `auto-run` before the first ask or review handoff.
- What the user says about auto-run is saved in `.claude/kit/settings.json` and holds in every session until it is changed (the user, 2026-11-16): asked to turn it on or off, enable or disable it, start or stop it - in any words - do as said. Where that request's `kit status` line carries `saved: auto_run=`, the status hook saved it; where it does not, run `node .claude/kit/settings.mjs set auto_run on` (or `off`) yourself and say what it printed.
- Where no `kit status` line arrives: run `node .claude/kit/settings.mjs` before the session's first ask, and again before the next ask after a compaction.

# Grade a draft before asking for its approval

- A spec, design doc or implementation plan written for the user's approval in this repo (`docs/superpowers/specs/` and `docs/superpowers/plans/` included) is graded with the `refining-plans` skill BEFORE the step that asks the user to review it, after the author's own self-review. Why: the user's bar is 9 or 10 out of 10 from an independent grade, and they should not have to ask for it (the user, 2026-10-24).
- The handoff carries the score path; a draft handed over ungraded is the failure this rule exists for.
- What the user says about scoring is saved in `.claude/kit/settings.json` and holds in every session until it is changed (the user, 2026-11-16): asked to turn it on or off, enable or disable it, start or stop it - in any words - do as said. Where that request's `kit status` line carries `saved: scoring=`, the status hook saved it; where it does not, run `node .claude/kit/settings.mjs set scoring on` (or `off`) yourself and say what it printed.
- `scoring=off` on the `kit status` line, or the user's own word in this session to stop it, turns this rule off, and the handoff says why: `ungraded - scoring stopped` in the session where the user said it, else `ungraded - scoring off in the settings`. Where no `kit status` line arrives, run `node .claude/kit/settings.mjs` before a draft is handed over.

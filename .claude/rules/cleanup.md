# Clean up what the run made when the work ends

- When a task ends - finished or given up - and before its close, remove or stop what this run made or started that nothing needs any more. Why: leftovers - branches, stashes, a running Docker or Windows VM - cost the user disk, memory and a cleanup by hand (the user's ruling, 2026-11-19).
- A run that waits - for an approval, a push, another `auto-run` stop, the user's next word after an interrupt - has not ended: it removes nothing and names what still runs.
- Record each thing when it is made or started - a branch name, a stash message, a worktree path, a PID or task id, a container id, and for Docker or a virtual machine whether it was already running - in the ledger or the todo list. Remove it by that identity alone, never by position (`stash@{0}`), by class (`git branch --merged`, `git clean`, a `prune`, `down -v`) or by port. A thing with no record is not the run's: a redundant thing it only found - an old merged branch, a stash from another day - is named in the close and left.
- Git: a local branch the run made whose commits are all on another branch (`git branch -d`, never `-D`), a stash the run made whose content is back in the tree or in a commit, and a worktree the run added that holds nothing uncommitted (`git worktree remove`, never `--force`).
- Files and processes: temp folders, probe homes and throwaway fixtures the run wrote outside the scratchpad; background commands, servers, watchers and scheduled wakeups it started.
- Services: stop each container the run started. Then quit Docker, or shut a virtual machine down - the Windows VM included - only when both hold: this run started it, and a check made then shows nothing else uses it - for Docker, no container or build this run did not start; for a machine, no job or connection but the run's own. One that was already running stays running, and so does one the check cannot clear; the close names each and says whether it is idle.
- Cleanup never discards work: a branch with unmerged commits, a stash whose content is nowhere else and an uncommitted change stay. So does what the user asked for and what a later step needs - a server or a container they asked to have, a branch that waits for its push, a worktree under review. A record is not a leftover: a spec, a plan, a ledger, a score or plan file and an audit's results stay.
- A subagent seat removes only what the seat itself made and stops only what it started. It never quits Docker, shuts a machine down or removes its worktree: it reports what it left, and the session that dispatched it makes the end check.
- Cleanup opens none of `auto-run`'s stops: a removal that skill stops on - a file outside the scratchpad and the docs root with no other copy - is left while `auto-run` is on. A removal a guard asks about takes the guard's safe option, and one the permission mode denies is not retried or routed around. Each is named on the `Cleanup:` line.
- The close carries a `Cleanup:` line after its checks: what was removed or stopped, and what was left with its reason. A reply with no close, and a run that made and started nothing, has none.

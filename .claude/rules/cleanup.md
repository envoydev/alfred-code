# Clean up what the run made when the work ends

- When a task ends - finished or given up - and before its close, remove or stop what this run made or started that nothing needs any more. Why: leftovers - branches, stashes, a running Docker or Windows VM - cost the user disk, memory and a cleanup by hand (the user's ruling, 2026-11-19).
- A run that waits - for an approval, a push, another `auto-run` stop, the user's next word after an interrupt - has not ended: it removes nothing and names what still runs.
- Record each thing when it is made, started or, for Docker or a virtual machine, first used - a branch name, a stash message, a worktree path, a PID or task id, a container id, and for Docker or a virtual machine whether it was already running - in the ledger or the todo list. Remove it by that identity alone, never by position (`stash@{0}`), by class (`git branch --merged`, `git clean`, a `prune`, `down -v`) or by port. A thing with no record is not the run's: a redundant thing it only found - an old merged branch, a stash from another day - is named in the close and left.
- Git: a local branch the run made whose commits are all on another branch (`git branch -d`, never `-D`), a stash the run made whose content is back in the tree or in a commit, and a worktree the run added that holds nothing uncommitted (`git worktree remove`, never `--force`).
- Files and processes: temp folders, probe homes and throwaway fixtures the run made outside the scratchpad; background commands, servers, watchers and scheduled wakeups it started.
- Services: stop each container the run started. Then quit Docker, or shut a virtual machine down - the Windows VM included - only when both hold: this run ran a container, a build or a job on it, and a check made then shows nothing else uses it - no container, build, job or connection but the run's own, and no other `claude` session running on the machine. Who started it does not decide (the user's request, 2026-11-19): one that was already running is quit the same way once the check clears it. A machine that was already running and has a signed-in session stays, since that session can hold unsaved work. A machine gets a clean shutdown, never a forced stop: on Windows a `shutdown` with `/f`, or with `/t` above 0, forces. One the check cannot clear, or that does not go down, stays running, and the close names it and says whether it is idle.
- Cleanup never discards work: a branch with unmerged commits, a stash whose content is nowhere else and an uncommitted change stay. So does what the user asked for and what a later step needs - a server or a container they asked to have, a branch that waits for its push, a worktree under review. A record is not a leftover: a spec, a plan, a ledger, a score or plan file and an audit's results stay.
- A subagent seat removes only what the seat itself made and stops only what it started. It never quits Docker, shuts a machine down or removes its worktree: it reports what it left, and the session that dispatched it makes the end check, with each seat's use counted as its own.
- None of this is one of `auto-run`'s stops, as that skill says: each removal is of a thing this run made and recorded that holds no work, and one that holds work stays. A removal a guard asks about takes the guard's safe option, and one the permission mode denies is not retried or routed around. Each is named on the `Cleanup:` line.
- The close carries a `Cleanup:` line after its checks: what was removed or stopped, and what was left with its reason. A reply with no close, and a run that made and started nothing, has none.

# System audit - operating principles

Read before Phase 0: these define what counts as a defect in every later phase.

- Seams only. A defect that lives inside one part - a skill's trigger, a hook's exit contract, a rule's
  wording, a seat's tool scope, the template's facts - is that part's audit's. This audit reports it as a
  handoff row with its evidence and moves on; it never re-grades the part. What it owns is what sits
  BETWEEN parts: two homes for one job, two parts telling the model opposite things, a guard that denies
  a step a flow requires, a cite to something the profile does not install, the sum of what a session is
  sent, the routes around a guard, the facts a fresh session is or is not handed.
- Measure the install, not the catalog. Lint check 33 holds the repo's catalog; a session is sent what ONE
  install holds, beside every other plugin enabled there. The unit of evidence is a profile fixture of this
  working tree and its `session-surface.js` map. Never infer a load from a file's presence: a pathless
  rule loads, a path rule waits for a matching file, a manual-only skill is not listed, a denied seat
  leaves the listing, a hook's injection is what it printed on the probe.
- Ground every claim in a row, a line or an output. A conflict quotes both sides with file and line; a
  cost cites the map row; a gap names the tool, the route and the absent guard; an awareness fact names
  the row that states it. 'Overlaps with', 'seems heavy' and 'might confuse' are not findings.
- Both directions of tokens. Overuse is context paid with no measured use; underuse is a fact the stack
  could have stated that sessions re-derive by reading, measured in the corpus. A cut that makes sessions
  read more is not a saving.
- A hook earns its cost or leaves. Its cost is its latency and timeout exposure on every matching event,
  its injection on every turn it fires, and its false blocks; its value is the harm its true blocks
  prevented, read from the ledger, and the mandate it mechanizes. A hook that blocks a legitimate flow
  step with no receipt path is a conflict, not a safety feature.
- A guard is only as strong as its weakest route. Read every route to the same action: Bash, PowerShell
  and Monitor; Read, Grep and an MCP read tool; Write, Edit, NotebookEdit and an MCP edit tool such as a
  rename; the main session and every seat that holds the tool. A deny rule and a hook are both guards; an
  instruction in a rule is not.
- A fresh session is the test of awareness. What matters is what the model is HANDED at session start and
  after compaction, before it reads a file - not what it could find. The awareness checklist is fixed per
  profile before reading the map, so the map cannot shape the questions.
- Official docs are the authority. Every harness fact the scoring rests on - load order, listing budget,
  hook events and matcher semantics, deny semantics - is a currency row re-read at Phase 1b. A claim the
  docs do not carry is labelled community and never deducts on its own.
- A seeded default or a hook behaviour inside its observation week is recorded, not moved.
- Public repo. Fixture paths are scratch paths; the report names counts, shapes and the stack's own
  artifact names, never a consuming project's path or name. No absolute local path in any edit.
- Results stay, test data goes. The report, the checklist, the maps and the snapshot are kept under `RESULTS`; every
  fixture, export and matrix copy is deleted once the checks that read it have run (SKILL.md, 'Results and cleanup').
- Reversibility. Snapshot every file before editing (`RESULTS/snapshot/`) so a regression can be undone; a fix lands only on
  the user's answer to the one ask.

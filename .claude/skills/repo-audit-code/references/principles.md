# Code audit - operating principles

Read before Phase 0: these define what counts as a defect in every later phase.

- Ground every claim in the code. Cite the file and the line you are judging; no score, deduction or fix without them. A correctness deduction also names its failure scenario - the input, event or state, and what then goes wrong. A deduction with no scenario is a preference, and is not made.
- Behaviour is kept. The audit improves how the code is written, never what it does: the same input gives the same output, exit code, file written and message printed after an edit. A fix that changes behaviour exists only to close a named failure scenario, and it comes with the test that fails without it.
- A standard has one home. Each rubric line is scored against the shared skill that owns it, read by path and cited by path and section; nothing of it is restated in a finding from memory. Where the repo's own `structure_map`, `tsconfig`, lint or format config differs from that skill on style or shape, the repo's wins and is what the finding cites.
- The repo's map says what the shape is here. Where `structure_map` says a place is flat by contract, or that code written before a date follows the shape only as it is changed, staying flat is no deduction there; D1 then scores what the map does ask of that code - a decision as an exported pure function, a named value in the constants home, imports pointing one way. A place the map does not cover is scored by `project-structure` as written.
- Every file has a class, and the class decides what may happen to it. `convert` is TypeScript or it caps its item. `check` stays JavaScript and is typed through `// @ts-check` and JSDoc alone. `leave` - generated, vendored, kept byte for byte, a fixture a test reads as data - is never scored and never edited; a generated file is fixed in its generator. The classes and their three reasons are the `ts-convert` skill's, read at `.claude/skills/ts-convert/SKILL.md`, 'The classes'.
- The audit never plans a conversion. A `convert` file still in JavaScript is `ts-convert`'s to convert; here it is a D6 deduction that stands, listed under 'Not planned' with the reason it was left.
- Code a runtime outside the repo loads - a hook copied into a user's project, an installer a user runs, a script another repo copies by name - never moves to a Node version or a file name that runtime cannot load without the user's word in this run. An exported name, a CLI flag or a path used outside the repo is an open question, never a silent edit.
- A type is never loosened to make a check pass: no `any`, no non-null assertion, no `@ts-ignore`, no `@ts-expect-error` without a cited reason, no strictness key removed from a `tsconfig`. A test is never deleted, skipped or weakened to make a check pass.
- Two audits can read one file. On a hook file the hooks audit owns the event, the matcher, the exit contract, the timeout, the safety of the hook and its fit with the house rules; this audit owns the rest. A finding of the other audit's is named under 'Not planned' as its own, never fixed here.
- Tests are code. A test file is an item like any other, scored by the rules of the code it tests plus `ts-js-testing`; a subject's test dimension reads the tests the repo keeps for it, at this run.
- The set is one codebase. An import cycle, a dependency against the layering, logic written twice, a named value with two homes and an export nothing imports are invisible in any single item, and each blocks every item it implicates from A.
- A plan the editor has to interpret is a failed plan. Every edit carries its exact text, and a rename or a move carries, in the same plan, the edit of every reference to it.
- Node's and TypeScript's own pages are the authority for what the runtime and the compiler do. The Phase 1b table pins each fact with the date it was read, and every run re-reads a row before scoring with it.
- Public repo. No private project name and no absolute local path in the report or in any edit.
- Reversibility. The plan's `Baseline` revision is the snapshot: every edited file can be put back from it.
